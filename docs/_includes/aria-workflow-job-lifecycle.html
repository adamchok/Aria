Submit

Client uploads payment proofs and bank data; the API persists files and enqueues work.

  • Endpoint: POST /api/v1/jobs (multipart) or continuous ingest → auto-batch.
  • Files stored in MinIO; job row created with status PENDING.
  • Celery task enqueued on Redis (inline fallback when Redis unavailable).
  • Webhook: job.created fires immediately.

Process

Worker runs the OpenAI Agents SDK pipeline; status progresses through stage-specific values (INGESTING, NORMALISING, MATCHING, REPORTING).

  • Progress updated per agent stage (progress_pct, agents_completed).
  • SSE stream: GET /api/v1/jobs/{job_id}/stream — poll fallback via GET /jobs/{id}.
  • Webhooks: job.stage_completed after each stage (ingestion, normalisation, matching, report).
  • Typical latency: < 60 s for a 50-transaction batch in mock or live mode.

Complete

Pipeline finishes; report stored and terminal status set.

  • COMPLETED — all matches resolved above threshold.
  • AWAITING_REVIEW — uncertain items (0.50–0.74) need human decision.
  • FAILED — unrecoverable extraction, storage, or pipeline error.
  • Results: GET /api/v1/jobs/{job_id}/results; webhooks job.completed or job.review_required.

Review

Optional human step when status is AWAITING_REVIEW.

  • GET /api/v1/jobs/{job_id}/review — returns only UNCERTAIN items.
  • POST /api/v1/jobs/{job_id}/review/{match_id} — confirm, reject, or manual_match (idempotent).
  • GET /api/v1/jobs/{job_id}/bank-entries — picker for manual match.
  • Results and export update immediately after each decision; job moves to COMPLETED.

Export

Download audit-ready Excel once results are available.

  • Endpoint: GET /api/v1/jobs/{job_id}/export
  • Sheets: Summary, Matched, Exceptions, Audit Log.
  • Includes human review outcomes when applicable.
  • Content-Disposition: attachment; filename="aria-reconciliation-{job_id}.xlsx"
